Per-target Rocq object correspondence
====================================

The independent temporary producer reads all thirteen complete-declaration
receipts and checks their exact source closures, recorded object hashes,
warning profile, command arguments and toolchain identity. Each target gets
a fresh scratch proofs directory containing only its first-party source
closure and the project snapshot. Compilation uses canonical relative source
arguments, the two recorded -R aliases, -q and -w +default. Every predecessor
compiles before the source that imports it. An independent rocq check follows
for the target module.

The runtime reports Rocq 9.1.1 compiled with OCaml 5.4.0. The project SHA256 is
5507a888eedd0cb8da4e5414d0882416b1bdcec0d1934fd9b87b189867e883b8 both before
and after the audit. The runtime binary directory remains a chat-only input.

The absolute argument and namespace changes produce different objects.
The two warning policies produce identical bytes on this target. The replay
interface must therefore enforce its source spelling, aliases and warning
profile independently; digest agreement supplies no separate warning-policy
attestation.

CayleyDicksonAlgebra compiled before Prelude exits 1 with an error locating
Prelude under OpenGororoba. Compiling Prelude first and then CayleyDicksonAlgebra
exits 0. A lexical sort of the closure is an invalid ordering for that chain.

The positive determinism result covers these thirteen targets, their exact
closures, this pinned runtime and the recorded execution interface. Another
toolchain, namespace, path spelling or warning contract needs its own replay.
