Original admission defect and corrected mechanism
The original inventory loader considered only verified/ and projected a proof
file's existence as kernel_checked. The canonical theorem tables consequently
represented 162 source files as checked executions. Source existence establishes
an inventory entry; a compiler/checker execution requires retained artifacts.

The new loader reconciles both proof roots with the exact disk-source set.
Duplicate entries, missing or unlisted sources, legacy-stem collisions, path
traversal, and symlinked project/source roots produce visible errors.
New entries receive source_only. Existing identities retain their stable ID,
legacy name, title, formal claim links, identity kind and explanatory metadata.
The stable THM namespace and legacy theorem-table namespace remain distinct.
Numeric filename prefixes reserve historical IDs and carry scientific links
only through explicit canonical claim relations.

The new typed sync operation inserts source identities and projections without
clearing canonical tables. Registered locator removal/movement is rejected.
The operation retains complete identity/projection prestate and poststate in
an append-only theorem_identity_events envelope, records the project snapshot,
and checks exact replay against the retained poststate and live source evidence.
Status changes are the existing-record mutation surface. Existing assumptions,
kernel_result narrative, replay command, falsifier, titles, links and source
fields remain their recorded values.

Kernel receipts and operator boundary
The typed kernel evidence operation promotes one registered identity only after
its source project, complete project-local Require closure, declaration headers,
compiler/checker exits, warning policy, assumption reports, logs and retained .vo
object match the supplied witness. The proof object must have the Rocq object
header and the witnessed source basename. Each output role uses a distinct file.
The checker log carries its context summary; each selected declaration carries
one labeled Print Assumptions block whose full axiom-name set matches the spec.
An empty set requires a declaration-specific closed-context result.

The receipt stores the exact input specification and complete theorem metadata
before/after in a kernel-evidence event. The narrative kernel_result field stays
separate. Later ordinary theorem binding can revise its narrative while the
receipt remains in append-only history. Activation selects the latest receipt
for the stable identity and validates the exact live project/source/artifact
hashes. A changed source, dependency, project, object or log removes its active
kernel_checked projection on the next sync; the historical receipt is retained.

These receipts are operator-declared execution provenance with byte and scope
validation. The API validates retained file correspondence and reported exits;
the API does not launch the compiler, authenticate a process trace, reproduce a
run, attest an executable/toolchain installation, or cryptographically prove
that a retained .vo was produced from a particular source. Fresh production and
independent checking remain the operator's execution obligations. Section
hypotheses generalized into theorem parameters remain part of the mathematical
statement even when Print Assumptions reports a closed global context.

Warning semantics and command boundary
The pinned Rocq 9.1.1 parser maps '+' to AsError, '-' to Disabled, and an
unprefixed name to Enabled. Thus +all and +default are fatal warning policies.
The strings @all and @default denote unsupported warning names in that parser.
The validator accepts fatal_all, fatal_default and default_severity separately.
Fatal-policy commands require the matching -w argument and reject later warning
policy overrides, quick/interface-only compilation and checker-admission flags.

Compiler tokens must contain rocq compile or coqc and name the witnessed source.
Checker tokens must contain rocq check, rocqchk or coqchk and name its logical
module. An opam exec wrapper is accepted. This bounded token correspondence is
not a shell interpreter or execution attestation. Repository-relative artifact
paths keep local machine paths out of retained canonical receipts.

Concrete connection and falsifier
Every Cayley-Dickson doubling admits epsilon(a,b)=(a,-b). The doubling product
proves epsilon(xy)=epsilon(x)epsilon(y). Equivalently, for an XOR-indexed basis,
epsilon(e_i)=(-1)^(highest_bit(i))e_i is a multiplicative Boolean character.
This action fixes every basis label and changes a diagonal sign direction.
Schafer's displayed derivation extension fixes the newly doubled unit u, so
exponentials of those derivations fix u. The standard finite-dimensional real
Lie-group identity-component argument then separates epsilon, which sends u to
-u, from that connected component. This paper-backed argument supplies a direct
falsifier for conflating a connected g2/G2 result with the full group. The report
records the derivation. The owner added
exact_annihilator::tests::doubling_reflection_preserves_all_sedenion_basis_products
in crates/algebra_analysis/src/exact_annihilator.rs. The retained test log
reports a passing cargo test --locked -p algebra_analysis --lib
doubling_reflection run. The test uses the existing cd_kernel::gourlay_epsilon,
checks all 256 sedenion basis-product pairs with exact equality, fixes scalar
one and negates the last doubling unit e8. The identity-component/group-level
argument has the primary-source/Lie-theory support above; a new Rocq certificate
for that group-level argument remains a separate evidence surface.

The same distinction explains the modular-arithmetic boundary: a signed-XOR
word can fix zero and retain an observable controlled diagonal phase, while its
label action remains the identity. The origin-fixed nontrivial N=21 modular map
is excluded from that restricted label-word family. Boolean target flips and
other reversible circuits operate in a larger family. Sign-span cardinality,
automorphism-group classification, reversible synthesis and physical QPU
admission have independent success criteria, including above dimension 4096.
